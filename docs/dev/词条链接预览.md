# 词条链接预览

正文里的站内词条链（`[文字](/entry/...)`）在可点击跳转之外，悬停约 280ms 后弹出摘要卡片。本文说明设计约定、调用链、组件状态和一次完整悬停的时序。

---

## 1. 设计约定

- **跳转与预览分离**：锚点始终是 `next/link`，不依赖预览是否成功。
- **查询键只有 `href`**：与库内 `entries.href` 相同，例如 `/entry/js`、`/entry/blog/foo`。不再拆 `path` / `#` 锚点。
- **谁能出预览**：仅 `classifyMarkdownHref` 判定为 `kind: "entry"` 的链接。外链、`#概述`、`entry/js`、`/entry/js#闭包` 都不会包这层组件。
- **预览是增强不是导航**：划过（不足 280ms）不请求、不弹卡；卡片与链接之间的空隙靠 180ms 延迟关闭桥接。
- **正文不认页内锚点**：目录跳转仍由左侧 `EntryToc` 处理，不走 Markdown 链接。

---

## 2. 从 Markdown 到卡片

```
[JavaScript](/entry/js)
        │
        ▼
EntryContent（react-markdown，components.a = MarkdownLink）
        │
        ▼
classifyMarkdownHref(href)
  ├─ entry    → EntryLinkPreview(href)     ← 可预览
  ├─ external → <a target="_blank">
  └─ invalid  → 灰色不可点 <span>
        │
        ▼  悬停满 280ms
fetchEntryPreview(href)
        │
        ▼
GET /api/entries/preview?href=/entry/js
        │
        ▼
classifyMarkdownHref 再次校验为 entry
        │
        ▼
getEntryPreviewByHref → getEntryPageDataByHref
        │
        ▼
{ title, href, excerpt }  （excerpt 由正文现算，不落库）
```

分类规则（`lib/wiki/entry-slug.ts`）：

| 输入 | kind |
|------|------|
| `https://…` / `http://…` / `//…` | `external`（外链可自带 `?` / `#`） |
| 含 `#` 或 `?` 的站内写法 | `invalid` |
| `/entry/` + 至少一段 | `entry` |
| 空、`entry/js`、`/wiki/...`、仅 `/entry/` | `invalid` |

## 3. 组件怎么拆

| 文件 | 职责 |
|------|------|
| `components/wiki/entry/markdown-link.tsx` | 只按 `kind` 选组件，不请求 |
| `components/wiki/entry/entry-link-preview.tsx` | 延迟开闭、定位、请求、缓存、portal 卡片 |
| `lib/api/entries.ts` → `fetchEntryPreview` | 浏览器 `GET`，4xx 当业务失败不抛 |
| `app/api/entries/preview/route.ts` | 校验 + 查库 |
| `lib/db/entries.ts` → `getEntryPreviewByHref` | 读当前版本，裁 `title / href / excerpt` |
| `lib/wiki/entry-excerpt.ts` | Markdown → 纯文本，默认最多 200 字 |

`EntryLinkPreview` 是 Client Component：要听指针、算视口、把卡片挂到 `document.body`。

假定调用方传入的已是规范 `href`，组件内不再 `normalize`。

---

## 4. 交互与定位

### 延迟

| 常量 | 值 | 作用 |
|------|----|------|
| `OPEN_DELAY_MS` | 280 | 进入链接/卡片后才打开并开始加载 |
| `CLOSE_DELAY_MS` | 180 | 离开后稍等再关，便于从链移到卡 |

`scheduleOpen` / `scheduleClose` 都会先清掉对方的定时器。链接和卡片都绑了同一对 enter/leave（以及 focus/blur），所以「出链 → 进卡」不会把卡关掉。

卸载时 `useEffect` 清理定时器。

### 定位

`computeCoords(anchor.getBoundingClientRect())`：

- 锚点在视口上半：卡片在下方（`top = bottom + 10`）
- 下半：卡片在上方（`top = top - 10`，再 `-translate-y-full`）
- 水平以锚点中心对齐，宽 320，左右距视口至少 8px

卡片用 `createPortal(..., document.body)` + `position: fixed`，避免被正文 `overflow` 裁切。`open` 后监听捕获阶段 `scroll` 和 `resize`，跟着锚点走。小三角的水平位置按锚点中心相对卡片左缘再算一次。

## 5. 状态

五个 React state（定时器在 ref 里，不算 state）：

| state | 初值 | 含义 |
|--------|------|------|
| `open` | `false` | 是否挂卡片（`v-if`） |
| `coords` | `null` | `fixed` 坐标与上下方向 |
| `loading` | `false` | 正在请求 |
| `preview` | `null` | 成功摘要 |
| `error` | `null` | 失败文案 |

卡片 DOM 条件：`open && coords`。

离开时 **只把 `open` 设为 false**，不重置 `preview` / `error` / `coords`。再悬停同一实例可以立刻画出上一份数据；跨实例靠模块级缓存。

### 一次完整悬停（缓存未命中、请求成功）

```
时刻              open   coords   loading   preview   error    画面
────────────────────────────────────────────────────────────────
进入（<280ms）     F      null     F         null      null     只有链接
280ms 到          T      有        T         null      null     「加载预览…」
请求成功          T      有        F         有        null     标题 + 摘要
链↔卡移动         T      有        F         有        null     不变
离开 +180ms       F      有        F         有        null     卡片卸掉
```

岔路：

- **缓存命中**：280ms 时同步写入 `preview`，不走 `loading=true`，可能跳过「加载预览…」。
- **词条不存在**：`error` 有文案，`preview` 仍为 null；该结果写入缓存。
- **网络失败**：`error = "预览加载失败"`，**不写缓存**，下次可重试。

## 6. 取数与缓存

打开卡片时才调用 `loadPreview`（与 280ms 同拍），mount 不预拉。

```
previewCache: Map<href, { ok, data } | { invalid, error }>
```

- 成功与「业务无效」都缓存，同一页同一 `href` 不打第二枪。
- 网络异常不缓存。
- `Map` 在模块作用域，刷新或离开该 JS 上下文才清空；词条改了之后同页可能仍是旧摘要。

服务端 `getEntryPreviewByHref` 目前复用整页 `getEntryPageDataByHref` 再裁 excerpt，单次悬停偏贵，靠缓存兜。

读模型：

```ts
interface EntryPreviewData {
  title: string;
  href: string;    // 库内 canonical，卡片标题链到这里
  excerpt: string;
}
```

## 7. 时序（成功悬停）

```
t=0      pointerenter 链接
         scheduleOpen → 280ms 定时器（state 不变）
t=280    updatePosition → setOpen(true) → loadPreview
         portal 卡片，「加载预览…」
t=≈400   JSON 返回 → setPreview + 写入 Map
         标题 + excerpt
         （用户可点标题或原来的链接跳转）
离开链接  scheduleClose → 180ms
  若进入卡片  scheduleOpen 取消关闭
离开卡片  180ms 后 setOpen(false)
```

单击链接文字：App Router 去 `href`，与预览无关。  
单击卡片标题：去 `preview.href`，并立刻关卡。

---

## 8. 实现备忘

- `useCallback` 钉住 `clearTimers` 等函数引用，避免 `useEffect` 依赖变化时误清 280/180ms 定时器（React 函数组件每次 render 都会新建函数；Vue setup 无此问题）。
- `role="tooltip"` 对可点标题的卡片略勉强，更接近 hover card；键盘 focus 能打开，但 Tab 进卡片内链不顺（blur 会关）。
- 不要在预览组件里再解析 href；分类只在 `classifyMarkdownHref`。
- 编辑规范：`/wiki/guidelines` 写明必须 `/entry/...`，禁止正文 `#` 跳转。

---

## 9. 后续可做

- 预览查询改为只 select 标题 + 正文摘要，避免走完整阅读页组装（面包屑 / 相关树 / 贡献者）。
- 缓存加版本或短 TTL，避免同页看到过期 excerpt。
- 无障碍改为 hover-card 模式（Esc 关闭、焦点可移入卡片）。

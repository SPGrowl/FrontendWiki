# 重点理解清单：代码块与 JS 沙盒

面向本仓库「Markdown 代码块 → 在沙盒中运行」能力的速查清单。实现日期：2026-08-09。

---

## 1. 整体链路

- [ ] 词条正文 / 编辑预览都走 `EntryContent` → `react-markdown`。
- [ ] 块级 `code` 映射到 Client 组件 `MarkdownCodeBlock`（工具条 + 代码区）。
- [ ] 点击「在沙盒中运行」调用 `openRunner({ code })`。
- [ ] `JsRunnerProvider` 写入 `pendingCode` 并打开面板。
- [ ] `JsRunnerPanel` 消费 `pendingCode` → `setCode` → `clearPendingCode`。
- [ ] 用户再点「运行」时，经 `runInSandbox` 在隔离 iframe 中执行。

```
Markdown 围栏
  → EntryContent (components.code)
  → MarkdownCodeBlock
  → openRunner({ code })
  → JsRunnerContext.pendingCode
  → JsRunnerPanel.setCode
  → runInSandbox(code)
```

## 3. 块级 vs 行内代码

必须分清，否则行内 `` `code` `` 会被误渲染成大块：

| 条件 | 视为 | 渲染 |
|------|------|------|
| `className` 含 `language-xxx` | 块级 | `MarkdownCodeBlock` |
| 文本含换行 `\n` | 块级 | `MarkdownCodeBlock` |
| 其余 | 行内 | 默认 `<code>` |

`pre` 组件刻意写成 `<>{children}</>`，避免 `pre > MarkdownCodeBlock` 双重外壳。

---

## 4. 可运行语言（当前）

仅以下标签显示「在沙盒中运行」（沙盒跑浏览器 JS，不含 TS 编译）：

- `js` / `javascript`
- `mjs` / `cjs`
- `jsx`

`ts` / `tsx` **不**自动运行；作者应提供等价 JS 示例，或后续再加转译层。

作者写法：

````markdown
```js
console.log(1 + 2);
```
````

## 5. Context API 约定

```ts
openRunner();                    // 侧栏入口：只打开，不改编辑器内容
openRunner({ code: "..." });     // 代码块入口：打开并注入代码
```

- `pendingCode` 是一次性队列：Panel 读入后必须 `clearPendingCode()`，防止重复覆盖。
- Provider 已在根布局挂载；`MarkdownCodeBlock` / 侧栏均可 `useJsRunner()`。

---

## 6. 安全与边界

- [ ] 沙盒 iframe 仅 `allow-scripts`，无 `allow-same-origin`，降低读主站 DOM/Cookie 风险。
- [ ] 默认有执行超时（见 `run-in-sandbox.ts`）。
- [ ] 「在沙盒中运行」只是把源码拷进编辑器，**不会**自动执行；需用户再点运行（或快捷键 Ctrl/⌘+Enter）。
- [ ] 剪贴板 API 失败时复制按钮静默失败，不打断阅读。

---

## 7. 样式注意点

- 块级外观由 `.wiki-code-block` 负责；`.wiki-prose pre` 通用样式已去掉，避免与工具条叠两层边距。
- 行内 `code` 仍用 `.wiki-prose :where(code)`。
- 预览区（`EntryEditorPreviewPanel`）复用同一 `EntryContent`，编辑时即可试跑示例。
